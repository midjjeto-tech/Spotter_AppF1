# Голос инженера отдельно от комментатора — дизайн

Дата: 2026-07-09
Статус: утверждён пользователем (диалог 2026-07-09), реализация — по плану в
`docs/superpowers/plans/`.

## Контекст

Сразу после закрытия Фазы 1 «замены инженера» (точный box-вызов, см.
`2026-07-09-precise-box-call-design.md`) пользователь предложил логичное
развитие: командные реплики должен произносить ГОЛОС ИНЖЕНЕРА (персона `calm` —
она в `commentator/personas.py` буквально описана как «гоночный инженер на
пит-уолле» и уже имеет собственный голос: Yandex `marina` / Piper `irina`),
а выбранная пользователем персона комментатора — давать поверх этого свою
короткую реплику в третьем лице («Гонщик через круг едет на пит»).

Утверждено пользователем:
1. Это ОБЩИЙ принцип на всё будущее «инженерное» содержимое (Фазы 2-4: сводки
   по гэпу, топливо/ERS, погода) — строим переиспользуемый механизм сейчас.
2. Реплика комментатора идёт обычным пайплайном (LLM в выбранной персоне,
   шаблон как фолбэк) — toxic съязвит про пит-стоп, hype взорвётся.

## Проблема

`voice.say(text, priority)` кладёт текст в очередь и сразу возвращается;
реальный синтез происходит позже в фоновом потоке `TTSQueue._worker`
(`new_tts/queue_handler.py`), а персона читается из `self._current_persona`
В МОМЕНТ ПРОИГРЫВАНИЯ (`voice/tts.py::_play_blocking`, строка ~326). Способа
сказать «эту конкретную фразу — голосом инженера» нет.

**Отклонённый вариант А:** временно флипать `voice._current_persona` вокруг
вызова `say()`. Гонка: воркер может прочитать персону после восстановления —
тот же класс межпоточного бага, что уже ловили с `sd.play`/`sd.stop`
(CONTEXT.md, «Известные gotchas»). Второй экземпляр той же грабли не заводим.

**Принятый вариант Б:** персона — явный параметр, протащенный через очередь.
Низ пайплайна (`_synthesize`, `_generate_and_cache`, `_voice_key`, кэш) УЖЕ
параметризован персоной — переключается только верхний слой.

## Решение (одним абзацем)

`Voice.say()` получает опциональный параметр `persona` (по умолчанию `None` =
текущая персона — существующее поведение байт-в-байт); `TTSQueue` несёт его в
элементе очереди до `_play_blocking`. Маршрутизация «кто говорит» — признак
`event["speaker"] = "engineer"` на событии: `_commentary_loop` передаёт
`persona="calm"` для таких событий. Все strategy-AI события (`STRAT_BOX_CALL_*`,
`STRAT_PIT`, `STRAT_UNDERCUT`, ... — по смыслу это всё реплики инженера)
помечаются `speaker: "engineer"` при постановке в очередь. Рядом с box-вызовом
tier 1 engine ставит новое обычное событие `PIT_CALL_NOTICE` БЕЗ `speaker` —
его озвучивает комментатор в выбранной персоне обычным пайплайном.

## Не входит в объём

- Отражение «мгновенного» голоса инженера на UI-странице Voice (она показывает
  голос по `_current_persona`) — принятое ограничение.
- Отдельный волюм-слайдер/настройки для «канала инженера» — используется уже
  существующий per-persona волюм персоны `calm`.
- Изменение фраз/логики самого box-вызова — только маршрутизация голоса.
- `_backup_pre_*` папки не трогаем.

## Архитектура

### `new_tts/queue_handler.py` — `TTSQueue`

Элемент очереди: `(prio, seq, text)` → `(prio, seq, text, persona)`,
`persona: str | None`. Сигнатуры:

```python
def enqueue(self, text: str, priority: str = "normal",
            persona: str | None = None) -> None: ...
# worker:
self._speak_fn(text, persona)
```

`speak_fn` теперь принимает два аргумента. Оба реальных speak_fn обновляются
(см. ниже); `None` = «текущая персона на момент проигрывания».

**Ломающее следствие для тестов:** существующие тесты
`tests/test_queue_priority.py` создают `speak_fn` как однорукие лямбды
(`lambda t: ...`) — контракт `speak_fn(text, persona)` их сломает. Все
фейковые speak_fn в этом файле обновляются на два аргумента в той же задаче,
что меняет `TTSQueue` (не отдельной).

### `voice/tts.py` — `Voice`

- `say(self, text, priority="normal", persona=None)` — прокидывает в
  `self._queue.enqueue(..., persona=persona)`.
- `_play_blocking(self, text, persona=None)` — первая строка:
  `persona = persona or self._current_persona`; дальше существующий код без
  изменений (кэш-ключ `_voice_key(persona)` уже корректно разведёт
  `y:...marina...` инженера и голос комментатора — фразы не перемешаются).
- `_play_streaming(text, persona)` — уже принимает персону; внутри читает
  `self._effective_volume()` — перевести на параметр (см. следующий пункт).
- `_effective_volume(self, persona=None) -> float` — параметр вместо чтения
  `self._current_persona` (persona=None = текущая). Вызовы: `_play_streaming`
  (строка ~396) и `_play_wav` (строка ~520) — `_play_wav` получает опциональный
  параметр `persona`, который передаёт `_play_blocking` (два вызова:
  кэш-хит и после синтеза).
- `_say_pyttsx3_blocking(self, text, persona=None)` — принимает и игнорирует
  (у pyttsx3 один системный голос).

### `core/engine.py` — маршрутизация

1. Все strategy-AI события получают `"speaker": "engineer"`:
   - блок box-вызова (`STRAT_BOX_CALL_{tier}`, `_maybe_snapshot`, ~строка 1044);
   - advisory-блок (`_st_code_map` → `STRAT_PIT`/`STRAT_UNDERCUT`/...,
     ~строка 1074).
2. `_commentary_loop`, вызов озвучки (~строка 1759):
   ```python
   self.voice.say(
       phrase, priority=voice_priority,
       persona="calm" if event.get("speaker") == "engineer" else None)
   ```
3. Рядом с `STRAT_BOX_CALL_1` (ТОЛЬКО tier 1 — не спамим на эскалации) engine
   ставит второе событие:
   ```python
   if box_tier == 1:
       self._enqueue_event({
           "event_code": "PIT_CALL_NOTICE", "priority": "normal",
           "driver": "", "color": "#38BDF8",
       })
   ```
   Без `speaker` → голос комментатора. Обычный пайплайн: `build_plan` + LLM в
   выбранной персоне, шаблон при недоступности LLM. Обычная важность (50) —
   если есть что-то важнее, планировщик отложит/выкинет: команда уже прозвучала
   голосом инженера, реплика комментатора — колорит, не информация.

Порядок озвучки гарантирован очередью: box-вызов critical (прерывает, играет
первым), реплика комментатора normal (следом).

### `commentator/templates.py` — фразы `PIT_CALL_NOTICE` (фолбэк без LLM)

```python
"PIT_CALL_NOTICE": [
    "Гонщику дали команду — в этом круге едет на пит.",
    "Инженер зовёт в боксы. Смотрим, послушается ли.",
    "Команда с мостика: пит-стоп в этом круге.",
    "С пит-уолла прозвучало «бокс» — ждём заезда.",
],
```

### Если выбранная персона — сама `calm`

Ничего особенного: `persona="calm"` совпадает с текущей, инженер говорит своим
голосом, `PIT_CALL_NOTICE` тоже озвучит `calm`. Осознанно: пользователь сам
выбрал слушать только инженера. Гейтов не добавляем.

## Граничные случаи

- **pyttsx3-резерв** — второй аргумент принимается и игнорируется; поведение
  как сейчас.
- **Кэш** — разведён по построению: `_voice_key(persona)` даёт разные ключи
  для инженера и комментатора; фраза, закэшированная голосом инженера, никогда
  не проиграется голосом комментатора и наоборот.
- **Volume/radio-fx** — radio-fx глобальный тоггл (не per-persona), volume
  становится параметром (см. выше); фраза инженера играется с волюмом персоны
  `calm` из настроек.
- **`PIT_CALL_NOTICE` вне гонки** — box-вызов сейчас не гейтован по
  session_type (принятое ограничение Фазы 1), значит и notice не гейтуем —
  симметрично. Если Фаза 1 когда-то получит гейт, notice получит его
  автоматически (он ставится только рядом с tier 1).
- **LLM молчит на `PIT_CALL_NOTICE`** (вернул тишину) — нормально, фраза
  пропадает, команда инженера уже прозвучала.

**Найдено и исправлено финальным сквозным ревью после реализации (Critical):**
`PIT_CALL_NOTICE` гасился ПОЧТИ КАЖДЫЙ РАЗ порогом «говорить/молчать»
(`_speak_threshold` в `_commentary_loop`) — он ставится в очередь В ТОТ ЖЕ
тик, что и critical box-вызов, который сам только что поднял спайк порога
(65+, до 85 в calm/story режиме) при своей озвучке; обычная важность notice
(50, дефолт) при `now ≈ _last_voiced_at` ВСЕГДА оказывалась ниже свежего
спайка → реплика комментатора молча гасилась, не доходя даже до
`session_guard`. Поднять importance до критического порога (90) было нельзя —
это переключило бы приоритет на critical, что семантически неверно для лёгкой
реплики-колорита. **Фикс:** новый флаг события `bypass_speak_threshold`
(симметричный уже существующему исключению для `AMBIENT`) — `PIT_CALL_NOTICE`
ставится с этим флагом, гейт (вынесен в отдельный тестируемый метод
`_muted_by_threshold`) его учитывает. Cooldown `session_guard.py` (см. выше)
и остальные гейты (`_is_stale_backlog_event`, флешбек-тишина, ситуационный
дедуп) по-прежнему применяются — bypass касается ТОЛЬКО порога важности.
Независимо перепроверено вторым ревью после фикса.

## Тестирование

- `tests/test_queue_priority.py` (существующий файл тестов `TTSQueue`) —
  новые: enqueue с персоной доставляет её в speak_fn; без персоны — `None`;
  critical-путь тоже несёт персону.
- `tests/test_tts_playback_stream.py` (паттерн уже есть) — `_play_blocking`
  с переданной персоной использует её для кэш-ключа (не `_current_persona`);
  без персоны — текущую.
- `tests/test_engine_planner.py` — `STRAT_BOX_CALL_*` и advisory несут
  `speaker: "engineer"`; `PIT_CALL_NOTICE` ставится рядом с tier 1 и НЕ
  ставится на tier 2/3.
- `tests/test_phrases.py` или новый — фразы `PIT_CALL_NOTICE` на месте.
- Живая проверка голосов (реально ли слышно два разных голоса подряд) — у
  пользователя после сборки, в среде разработки аудио нет.
