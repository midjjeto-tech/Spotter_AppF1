# Career Memory (cross-race personal history) — Design Spec

**Дата:** 2026-07-03
**Статус:** утверждён (дизайн), готов к плану реализации
**Источник:** «Идея 10» из конкурентного анализа (упоминалась как отложенная в спеке
Post-Race Story), решение пользователя продолжить «идти вглубь F1 25» после
F1 Sector Benchmark.

## 1. Обзор

Сегодня каждая гонка — чистый лист: приложение не помнит, что игрок уже ездил на этой
трассе раньше. Career Memory даёт три поверхности сравнения с СОБСТВЕННОЙ историей
игрока (не с реальным F1 — это отдельная, уже реализованная фича Real-F1/Sector
Benchmark):

1. **HUD в гонке** — гэп к личному лучшему кругу на этой трассе за всю историю.
2. **Голосовая реплика** — на новом личном рекорде СЕКТОРА (и полного круга) трассы.
3. **Post-Race Story** — факт «быстрее/медленнее, чем в прошлый визит» (другая метрика,
   не «рекорд», а прогресс с ПОСЛЕДНЕГО раза).

Источник данных — уже существующий архив (`analytics/archive.py`,
`DATA_DIR/game_sessions/*.json`), никакой сети, никакого нового хранилища.

## 2. Две независимые метрики (важно не путать)

- **`best_ever`** — лучший круг (+секторы) игрока на этой трассе за ВСЮ сохранённую
  историю. Фиксированная цель для побития, как у Real-F1 Benchmark. Питает HUD и
  голосовые PB-реплики.
- **`last_visit`** — данные САМОЙ ПОСЛЕДНЕЙ по времени прошлой сессии на этой трассе
  (лучший круг того заезда + финишная позиция + дата). Питает ТОЛЬКО факт Post-Race
  Story («в прошлый раз ты финишировал P8 с лучшим кругом X — в этот раз P5 и Y»).

Это не одна цифра в двух местах — это два разных, независимо вычисляемых поля.

## 3. Цели и не-цели

**Цели**
- `best_ever`/`last_visit` вычисляются из уже сохранённых `game_sessions/*.json`
  (никакого нового формата хранения, никакой сети).
- Фильтр по `track_id` (надёжный числовой enum), НЕ по `track_name` (строка — источник
  прошлого бага "Unknown", см. `CONTEXT.md`).
- Скоуп — только `session_type == "race"` (как и Real-F1/Sector Benchmark): круги из
  практики/квалификации не сравнимы по стратегии/топливу/резине с гоночным темпом.
- HUD-панель «Личный рекорд трассы» + 3 секторных чипа (переиспользуют паттерн
  Real-F1 Sector Benchmark визуально, но отдельные данные).
- Голосовая реплика на новом личном рекорде — и полного круга, и отдельно секторов
  (зеркалит `pb_line`/`sector_pb_line` из `F1Benchmark`), с тем же анти-спам-принципом
  (только на улучшении, не каждый круг).
- Post-Race Story: новый факт `vs_last_visit` (быстрее/медленнее прошлого визита,
  изменение позиции, дата прошлого визита) — ОТДЕЛЬНО от `best_ever`-фактов и от
  существующего `weak_sector`/`weak_sector_vs_f1`.
- Voice Q&A получает контекст бесплатно через уже существующий `analytics_context`
  (по аналогии с Real-F1 Benchmark).
- Первый визит на трассу (нет истории) → `ready=False`, всё выключено без ошибок
  (как «Эталон реального GP подгрузится после первого круга» у Real-F1 Benchmark).

**Не-цели (YAGNI v1)**
- Учёт практики/квалификации в `best_ever`/`last_visit`.
- Сравнение «по кругам» с прошлым заездом, отличное от секторов (по-угловое —
  осознанно отклонено при выборе гранулярности live-реплики).
- Кросс-трековая статистика («ты прогрессируешь в среднем по всем трассам») —
  только по одной конкретной трассе за раз.
- Ограничение по году/сезону — `best_ever`/`last_visit` считаются по ВСЕЙ истории
  трассы, независимо от игрового года сохранённой сессии.
- Индекс/кэш архива — при реалистичных объёмах (десятки-сотни сессий) линейное
  сканирование в фоновом потоке достаточно быстрое; не усложняем.

## 4. Архитектура (юниты и границы)

### 4.1 `analytics/archive.py` — небольшое расширение

`list_game_sessions()` сейчас не отдаёт `track_id` в лёгкой сводке (только
`track_name`). Добавить поле `track_id` в возвращаемый словарь (уже есть в каждом
полном JSON через `SessionRecorder.finalize()`, просто не прокидывается в сводку).
Обратно совместимо — существующие потребители (UI-архив) получают одно новое поле,
которое просто игнорируют.

### 4.2 `core/career_memory.py` (новый) — `CareerMemory`

Зеркалит форму `core/f1_benchmark.py::F1Benchmark`, но без сети/кэша/rate-limit —
источник локальный диск.

- `load(track_id: int) -> bool` — фильтрует `archive.list_game_sessions()` по
  `track_id` И `session_type == "race"` (список уже отсортирован новыми-сначала —
  первое совпадение = `last_visit` без доп. сортировки); для КАЖДОГО совпадения
  читает полный JSON (`archive.load_game_session(path)`, `None` — пропустить) и
  сводит: `best_ever` = минимальный `last_lap_ms` (+соответствующие s1/s2/s3) среди
  ВСЕХ кругов ВСЕХ совпадающих сессий; `last_visit` = финальная позиция + лучший круг
  ПЕРВОЙ (самой новой) совпадающей сессии. `True`, если найдена хотя бы одна прошлая
  сессия на этой трассе.
- `ready` property — `self.reference is not None` (как у `F1Benchmark`).
- `reset()` — вызывать на смене трассы (как `f1_benchmark.reset()`).
- `compare(player_laps: list[dict]) -> dict | None` — гэп ЛУЧШЕГО круга текущей гонки
  к `best_ever`. Ключ `"sectors"` присутствует ВСЕГДА (словарь либо `None`), тот же
  контракт, что у `F1Benchmark.compare()`.
- `pb_line(cmp) -> str` — реплика на новом личном рекорде ПОЛНОГО круга трассы.
- `sector_pb_line(sector_n, sector_cmp) -> str` — реплика на новом личном рекорде
  СЕКТОРА (мостик к анти-спаму — см. §4.3).
- `story_facts() -> dict` — `{"vs_last_visit": {"laptime_delta_ms": int, "position_delta": int,
  "last_visit_date": str} | None}` — сравнение ТЕКУЩЕГО финиша с `last_visit` (не с
  `best_ever`!). Вызывается в конце гонки, отдельно от per-lap `compare()`. **Знаки
  (фиксируем явно, чтобы не гадать при реализации):** `laptime_delta_ms = current_best_ms -
  last_visit_best_ms` — ОТРИЦАТЕЛЬНЫЙ = быстрее, чем в прошлый раз (тот же знак-конвенция,
  что `gap_ms` везде в проекте). `position_delta = last_visit_position - current_position` —
  ПОЛОЖИТЕЛЬНЫЙ = финишировал ВЫШЕ, чем в прошлый раз (P8→P5 даёт `8-5=+3`). Никакого
  единого `improved: bool` — время и позиция могут разойтись (быстрее, но ниже из-за чужой
  аварии), два независимых знака фразируются в `_format_facts` независимо друг от друга.
- `context_line(cmp) -> str` — строка-сверка для LLM (Voice Q&A получает бесплатно
  через `analytics_context`, как у `F1Benchmark`).

### 4.3 `core/engine.py` — оркестрация

- `self.career_memory = CareerMemory()`, `self._career_best_ms: int | None = None`,
  `self._career_best_sector_ms: dict[int, int] = {}` — по образцу
  `f1_benchmark`/`_f1_best_ms`/`_f1_best_sector_ms`. Сброс в тех же ДВУХ точках (смена
  трассы, SSTA).
- `_start_career_memory_load(track_id)` — фоновый поток, вызывается РЯДОМ с
  `_start_f1_benchmark_load` (тот же триггер — определение трассы). Локальный диск
  быстрее сети, но фоновый поток всё равно правильный выбор (не блокировать телеметрию
  на I/O).
- `_update_career_memory()` — новый метод, вызывается РЯДОМ с `_update_f1_benchmark()`
  (тот же триггер — завершённый круг). HUD: `state["career_memory"] = {...,
  "sectors": cmp["sectors"]}`. PB-анти-спам: identично `_update_f1_benchmark`'ной
  логике «сектора» (наименьший `gap_ms` среди улучшенных → одна реплика), СОБЫТИЕ
  **`CAREER_SECTOR_PB`** (не `F1_SECTOR_BENCH` — разные события, разный смысл) +
  отдельное **`CAREER_PB`** на полном круге (аналог `F1_BENCH`).
- `_generate_story` — вызывает `self.career_memory.story_facts()`, threads
  `vs_last_visit` в `story_collector.facts(...)` как НОВЫЙ параметр (по образцу
  `weak_sector_vs_f1` из F1 Sector Benchmark).

### 4.4 `commentator/channel_router.py`

Новые коды `CAREER_PB`/`CAREER_SECTOR_PB` не требуют правок — безопасный дефолт
роутит всё неизвестное в commentary (тот же паттерн, что `F1_BENCH`/`F1_SECTOR_BENCH`).

### 4.5 `core/race_story.py` + `commentator/story.py`

`RaceStoryCollector.facts()` — новый kwarg `vs_last_visit: dict | None = None`,
проброс в возвращаемый словарь под тем же именем. `commentator/story.py::_format_facts`
— новый блок: если `vs_last_visit` не `None`, строка вида «В прошлый раз на этой трассе:
P{X}, круг {Y}. В этот раз: {быстрее/медленнее} на {Z}с, {лучше/хуже} на {N} позиций».

### 4.6 UI — `NewSpotterUI`

`lib/api.ts` — новый тип `CareerMemoryState` (гэп + секторы, форма как у
`F1BenchmarkState`) + поле `career_memory?` в `SpotterState`. `race.tsx` — новая панель
«Личный рекорд трассы» (тот же визуальный паттерн, что «Эталон F1»: число + 3 чипа,
цвет по `gap_ms <= 0`), с собственным пустым состоянием «Личный рекорд появится после
первого визита на эту трассу» при `career_memory` отсутствует/`null`.

## 5. Модель данных

```python
# CareerMemory.reference (после load())
{
    "best_ever": {"lap_ms": int, "sector_ms": {1: int, 2: int, 3: int} | None, "date": str},
    "last_visit": {"best_lap_ms": int | None, "final_position": int | None, "date": str},
}

# CareerMemory.compare() -> dict | None
{
    "gap_ms": int, "player_best_ms": int, "best_ever_ms": int, "best_ever_date": str,
    "sectors": {1: {"player_ms": int, "gap_ms": int}, 2: {...}, 3: {...}} | None,
}

# CareerMemory.story_facts() -> dict
# Знаки: laptime_delta_ms < 0 = быстрее прошлого визита; position_delta > 0 = финиш выше.
{"vs_last_visit": {
    "laptime_delta_ms": int, "position_delta": int, "last_visit_date": str
} | None}
```

`state["career_memory"]` (в `/api/state`) — те же поля, что `compare()`, плюс
`"sectors"`; изначально `None`.

## 6. Обработка ошибок / граничные случаи

| Ситуация | Поведение |
|---|---|
| Первый визит на трассу (нет прошлых `race`-сессий) | `load()` → `False`, `ready=False`, HUD не показывает панель, реплик нет, `vs_last_visit=None` в Story. |
| Архивный файл повреждён/отсутствует | `archive.load_game_session()` уже возвращает `None` — пропускаем эту сессию, остальные учитываем. |
| Текущая (ещё идущая) гонка | Не может попасть в свою же историю — `game_sessions/*.json` создаётся только при `finalize()` в конце сессии. |
| Лучший круг из прошлого без валидных s1/s2/s3 | `best_ever["sector_ms"] = None` для этой метрики; `compare()["sectors"]` тоже `None` (тот же all-or-nothing контракт, что у `F1Benchmark`). |
| Несколько PB-секторов в одном круге | Одна реплика (наименьший `gap_ms`), как у `F1_SECTOR_BENCH`. |
| `vs_last_visit` без `last_visit` (есть `best_ever`, но почему-то не он) | Не должно происходить (`last_visit` всегда есть, если есть `best_ever` — оба считаются из одного и того же набора файлов), но `story_facts()` возвращает `None` защитно, если `last_visit` пуст. |

## 7. Тестирование

- `tests/test_archive_track_id.py` (или расширение существующего archive-теста) —
  `list_game_sessions()` включает `track_id`.
- `tests/test_career_memory.py` (новый) — `load()`: нет истории → `False`; несколько
  сессий на трассе → `best_ever` берёт глобальный минимум, `last_visit` — самую новую
  (не самую быструю); фильтр по `session_type != "race"` исключает практику/квалу;
  повреждённый файл пропускается, остальные учитываются; `compare()` всегда содержит
  `"sectors"`; `story_facts()` считает `improved`/`laptime_delta_ms`/`position_delta`
  корректно (в т.ч. знаки — какое направление считается «улучшением»).
- `tests/test_engine_career_memory.py` (новый, по образцу `test_engine_f1_benchmark.py`)
  — анти-спам PB-реплики (полный круг + сектор), холодный старт, `sectors=None`
  деградация, сброс на смене трассы/SSTA.
- Расширения `test_story_collector.py`/`test_story_generator.py` — `vs_last_visit`
  сосуществует с `weak_sector`/`weak_sector_vs_f1`, не путается ни с одним из них.
- Полный `pytest` + `npx tsc --noEmit` зелёные.

## 8. Вне рамок (будущее)

- По-угловое сравнение с прошлым заездом (не только секторы).
- Кросс-трековая агрегированная статистика прогресса.
- Ограничение памяти по сезону/году.
- Индексация архива при очень большом числе сохранённых сессий.
