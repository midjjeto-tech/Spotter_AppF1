# Pit-Stop False Pace-Loss Spam — Design Spec

**Дата:** 2026-07-04
**Статус:** утверждён (дизайн), готов к плану реализации
**Источник:** живой баг-репорт пользователя — при заезде на пит-стоп комментатор
безостановочно озвучивает эскалирующие фразы про потерю темпа/рост отставания
(«Темп теряется» → «падает» → «рушится» → «ушёл» за ~20 секунд).

## 1. Обзор

Пит-стоп физически удлиняет круг (пит-лейн лимит + остановка) и временно раздувает
отрыв до лидера/машины впереди — это ОЖИДАЕМО, не потеря темпа на трассе. Приложение
сейчас не знает о существовании пит-стопов вообще: `core/packets.py` не парсит
`m_pitStatus` из телеметрии F1 25, хотя байт лежит прямо рядом с уже парсящимися
`m_carPosition`(+32)/`m_currentLapNum`(+33). Из-за этого несколько независимых систем,
построенных на сырых дельтах времени круга/отрыва, ложно интерпретируют пит-стоп как
провал гонки:

1. **Ambient-комментарий** (`commentator/timeline.py`) — репортит «замедляется»/
   «отрыв растёт» каждый тик (~раз в 2-5 сек), и поскольку числа реально продолжают
   расти пока машина стоит, анти-дубль-защита (SituationDedup) не срабатывает —
   каждое наблюдение технически новое и «хуже» предыдущего.
2. **driver_coach** (`core/coach_ai/analyzer.py`) — не сообщённый пользователем, но
   найденный при расследовании: consistency-score (дисперсия по всем кругам),
   pace_delta (среднее последних 3 кругов), tyre_advice (дельты последних 3 кругов)
   и weak_sector (среднее последних 5 кругов) — ВСЕ уязвимы к одному кругу-выбросу.
3. **F1 Sector Benchmark** (`core/f1_benchmark.py::race_weak_sector`) — среднее по
   всем кругам гэпа к реальному F1 по сектору; один пит-круг может ложно назначить
   «слабым» сектор, где физически проходит пит-лейн. Уточнение: это касается ТОЛЬКО
   `race_weak_sector()`. Метод `compare()` (используемый `_update_f1_benchmark()` для
   HUD и `F1_BENCH`/`F1_SECTOR_BENCH`-реплик) выбирает через `min()`, как и у Career
   Memory — структурно иммунен, изменений не требует.
4. **Career Memory** (`core/career_memory.py`) — проверено: `load()`/`compare()`/
   `story_facts()` выбирают через `min()`, структурно не могут выбрать искусственно
   медленный круг. Изменений не требует — явно фиксируем это, а не молча пропускаем.

## 2. Ключевая техническая тонкость

Есть ДВА разных типа сигнала, которые ведут себя по-разному во времени:

- **Живые значения** (`gap_leader_ms`, `gap_front_ms`) — обновляются каждый тик,
  реально растут ПОКА машина стоит в боксах. Подавляются проверкой ТЕКУЩЕГО
  `pit_status != 0` в момент рендера.
- **Ретроспективные значения** (`last_lap_ms` завершённого круга) — по семантике
  телеметрии F1 значение «время последнего круга» прикрепляется к снимку СЛЕДУЮЩЕГО
  круга (см. `commentator/timeline.py::record_snapshot`'s дедуп-по-кругу). Круг,
  включавший пит-стоп, заканчивается (пересечение финишной черты) когда игрок УЖЕ
  выехал из боксов — то есть к моменту, когда этот круг попадает в сравнение
  `_pace_trend()`, `pit_status` уже снова 0. Проверка «текущего» статуса НЕ поймает
  этот случай — нужен флаг «было ли пит-событие В ЛЮБОЙ момент этого круга»,
  накопленный (`OR` по тикам), а не «текущее значение».

Это значит: живые отрывы подавляются по текущему статусу; темп/консистентность/
weak_sector подавляются по флагу «этот КРУГ был связан с питом» — разные механизмы,
не взаимозаменяемые.

## 3. Архитектура (юниты и границы)

### 3.1 `core/packets.py` — парсинг `pit_status`

`parse_player_lap()` добавляет `"pit_status": data[base + 34]` (uint8, 0=нет,
1=заезжает, 2=в зоне пит-лейн — согласно спеке F1 25 UDP, байт сразу после уже
парсящихся `m_carPosition`@32/`m_currentLapNum`@33). Обновить комментарий-предупреждение
в `diag_lap_offsets.py`, добавив вывод байта 34 при живом прогоне — та же
осторожность, что уже применена к секторным оффсетам в этом файле.

### 3.2 `core/engine.py` — накопление флага «круг был пит-кругом»

- `self._current_lap_pit: bool = False` — новое поле, инициализируется в конструкторе,
  сбрасывается там же, где `self._prev_lap` (обе точки сброса сессии).
- В обработчике телеметрии, там же где читаются `gap_front_ms`/`gap_leader_ms` из
  `pl` (`core/engine.py:693-694`): `if pl.get("pit_status"): self._current_lap_pit = True`
  (накопление ИЛИ по тикам, не перезапись).
- В блоке завершения круга (`core/engine.py:710-731`, где сейчас вызываются
  `self.recorder.on_lap_complete(...)` и `self.driver_coach.add_lap(...)`):
  1. Захватить `lap_was_pit = self._current_lap_pit` ДО сброса.
  2. Передать `pit_lap=lap_was_pit` в `self.recorder.on_lap_complete(...)`.
  3. Вызывать `self.driver_coach.add_lap(...)` только `if not lap_was_pit` (полностью
     пропустить круг для coach-анализа — см. §3.3).
  4. Сохранить `self._last_completed_lap_was_pit = lap_was_pit` (новое поле) — читается
     `_maybe_snapshot()` для передачи в `RaceTimeline.record_snapshot(pit_lap=...)`.
  5. Сбросить `self._current_lap_pit = False` для следующего круга.
- `_maybe_snapshot()` дополнительно передаёт живой `pit_status` (из последнего `pl`,
  аналогично уже читаемым `gap_front_ms`/`gap_leader_ms`) в `record_snapshot(...)`.

### 3.3 `core/coach_ai` — НЕ изменяется

Полностью пропуская `driver_coach.add_lap(...)` для пит-кругов (см. §3.2), внутренняя
логика `analyzer.py` (`_weak_sector`/`_consistency`/`_pace_delta`/`_tyre_advice`) никогда
не видит контаминированные данные. `lap_count` в отчёте будет отражать «кругов,
использованных для анализа темпа», не точный номер круга гонки — приемлемая, не
вводящая в заблуждение семантика (коуч и не претендует быть счётчиком кругов гонки).

### 3.4 `core/session_recorder.py`

`on_lap_complete()` — новый параметр `pit_lap: bool = False`, сохраняется в словарь
круга (`self._laps.append({..., "pit_lap": pit_lap})`). Автоматически попадает и в
`self.recorder.laps()` (текущая сессия), и в `finalize()`'s `player_laps` (архив —
задел на будущее для `CareerMemory.load()`, хотя сегодня это не требуется благодаря
`min()`-отбору, см. §1.4).

### 3.5 `core/f1_benchmark.py::race_weak_sector()`

Одна строка фильтра в начале метода: `player_laps = [l for l in player_laps if not
l.get("pit_lap")]` — прежде чем считать `totals`/`counts` по секторам. Остальная
логика (включая тай-брейк «наименьший номер сектора при равенстве») не меняется.

### 3.6 `commentator/timeline.py::RaceTimeline`

- `record_snapshot()` — два новых параметра: `pit_status: int | None = None` (живой,
  на момент снимка) и `pit_lap: bool | None = None` (было ли пит-событие в ходе круга,
  чьё `last_lap_ms` несёт этот снимок). Оба сохраняются в словарь снимка как есть
  (дедуп-по-кругу мёрджит их так же, как остальные поля).
- `_pace_trend()` — вместо плоского списка времён собирает пары `(last_lap_ms, pit_lap)`;
  если `pit_lap` истинен у ЛЮБОГО из двух сравниваемых снимков — возвращает `None`
  (без тренда). Голая строка `"ТЕМП: круг {pace}."` (без тренда) при этом всё равно
  рендерится — это не вводит в заблуждение само по себе.
- `_gap_front_trend()` и рендер строки `"ОТРЫВЫ: ..."` — подавляются целиком (для
  ТЕКУЩЕГО снимка), если его живой `pit_status != 0`.
- `render()` — новая строка при живом `pit_status != 0` в текущем снимке:
  `"ФАЗА: ПИТ-СТОП — трасса не в счёт, не считай это потерей темпа."` (по аналогии с
  уже существующими `"ФАЗА: практика"`/`"ФАЗА: квалификация"`). Не заменяет
  лап-based фазу (старт/середина/финал) — добавляется отдельной строкой, если оба
  условия верны одновременно (поздний пит-стоп остаётся «концовкой» И «пит-стопом»).

## 4. Модель данных

```python
# core/packets.py::parse_player_lap() — новое поле в возвращаемом словаре
{"pit_status": int}  # 0=нет, 1=заезжает в пит-лейн, 2=в зоне пит-лейн

# core/session_recorder.py — новое поле в словаре круга (recorder.laps() и архив)
{"lap": int, "last_lap_ms": int, "s1_ms": int, "s2_ms": int, "s3_ms": int,
 "pit_lap": bool}

# commentator/timeline.py::RaceTimeline — новые поля снимка
{..., "pit_status": int | None, "pit_lap": bool | None}
```

## 5. Обработка ошибок / граничные случаи

| Ситуация | Поведение |
|---|---|
| Пит-стоп занимает несколько кругов подряд (редко, напр. долгая остановка/ремонт) | Каждый затронутый круг независимо получает `pit_lap=True` — накопление ИЛИ работает per-круг, не «залипает» после первого. |
| Пит-стоп короче 1 секунды троттлинга снимков | `_current_lap_pit` всё равно ловит его — накопление идёт по КАЖДОМУ телеметрия-тику (без троттлинга), не по снимкам. |
| Игрок НЕ питстопился весь заезд | `pit_status` всегда 0, `pit_lap` всегда `False` — поведение системы не меняется, все существующие тесты (704/1/0 → теперь с учётом Career Memory 756/1/0) остаются зелёными без изменений. |
| Старые архивные сессии (записаны до этого фикса) | `player_laps` в них не содержит `pit_lap` — `.get("pit_lap")` вернёт `None`/falsy, т.е. трактуется как «не пит-круг» (безопасный дефолт, не ломает `race_weak_sector` на старых данных). |
| SSTA / смена трассы | `self._current_lap_pit`/`self._last_completed_lap_was_pit` сбрасываются в тех же существующих точках сброса, что и `self._prev_lap`. |

## 6. Тестирование

- `tests/test_packets.py` — `parse_player_lap()` возвращает корректный `pit_status`
  для всех трёх значений (0/1/2) на синтетических байтах.
- `tests/test_engine_pit_tracking.py` (новый) — накопление `_current_lap_pit` по
  нескольким тикам одного круга; сброс на смену круга; `pit_lap=True` доходит до
  `recorder.on_lap_complete`; `driver_coach.add_lap` НЕ вызывается для пит-круга (но
  вызывается для обычного); `_update_f1_benchmark`/`_update_career_memory`
  по-прежнему вызываются ВСЕГДА, включая пит-круги — их `compare()`-логика
  структурно иммунна (см. §1 п.3 уточнение и п.4), пропускать их не нужно и не
  предусмотрено этим фиксом.
- `tests/test_session_recorder_laps.py` (расширить) — `on_lap_complete(pit_lap=True)`
  сохраняет поле; дефолт `pit_lap=False` для обратной совместимости вызовов без него.
- `tests/test_f1_benchmark.py` (расширить) — `race_weak_sector()` игнорирует круги с
  `pit_lap=True` при усреднении по секторам.
- `tests/test_timeline.py` (новый или расширить, если уже существует) —
  `_pace_trend()` возвращает `None`, если пит-круг участвует в сравнении (оба
  направления: пит-круг первый/второй из пары); `ОТРЫВЫ`-строка отсутствует при живом
  `pit_status != 0`; строка `"ФАЗА: ПИТ-СТОП"` появляется/отсутствует корректно;
  голый `"ТЕМП: круг {pace}."` без тренда всё ещё рендерится (не полностью пропадает).
- Полный `pytest` (ожидаемый бейслайн 756/1/0 → без изменений в счёте регрессии,
  плюс новые тесты) + `npx tsc --noEmit` (эта фича не трогает фронтенд — команда
  должна остаться чистой без изменений).

## 7. Вне рамок (будущее)

- Голосовая реплика, специально приветствующая/комментирующая сам пит-стоп (сейчас —
  только подавление ложных негативных реплик, не добавление новых позитивных).
- Изменение `core/career_memory.py` (подтверждено — не требуется сегодня).
- Обгон-спам (`OVTK`) во время стоянки в боксах — отдельный, не затронутый этой
  фичей вопрос (не был частью изначального репорта).
- Персист `pit_lap` для нужд, отличных от `race_weak_sector` (например, будущая
  фича «пит-стоп статистика по гонке») — не проектируется здесь, но поле уже
  доступно в архиве благодаря §3.4.
