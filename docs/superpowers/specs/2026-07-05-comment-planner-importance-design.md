# Comment Planner + Importance — дизайн ядра «живости комментария»

Дата: 2026-07-05
Статус: утверждён пользователем (диалог 2026-07-05), реализация — по плану в
`docs/superpowers/plans/`.

## Проблема

Сегодня `commentator/brain.py::create()` отдаёт LLM весь рендер `RaceTimeline`, и LLM
сам решает, о чём говорить. Это задокументированная корневая причина рассинхрона
триггер↔фраза (CONTEXT.md, «Известные gotchas»): модель пересказывает доминантную
драму таймлайна на ЛЮБОЙ триггер. `SituationDedup` — рабочая заплатка, не решение.
Приоритет событий бинарный (`critical`/`normal`), из-за чего:

- мелкое и важное некритичное событие ждут в одной FIFO-очереди на равных;
- вытеснение бэклога бинарное (`_is_stale_backlog_event`): любое некритичное событие
  выбрасывается, если в очереди есть что-то свежее — даже если выброшенное важнее;
- длина/эмоция фразы не зависят от значимости момента;
- прерывать текущую озвучку умеет только фиксированный список `CRITICAL_EVENTS`.

## Решение (одним абзацем)

Python-слой планирования: каждый прошедший фильтры event получает **важность 0–100**
(чистая функция от кода события и контекста гонки) и **план реплики** (фокус, тип
реакции, длина, эмоция, обязательные упоминания). LLM больше не выбирает тему — он
формулирует текст строго по директиве плана. Важность управляет четырьмя вещами:
порогом «говорить/молчать», порядком и вытеснением в очереди, стилем реплики и
прерыванием текущей озвучки.

Утверждённые решения пользователя:
1. Архитектура — «Python планирует, LLM формулирует» (не промпт-инжиниринг, не два
   LLM-вызова).
2. Объём — только ядро (планировщик + важность). Режим финала, гоночная память,
   phrase bank — отдельные последующие спеки поверх этого ядра.
3. Важность влияет на все 4 механизма (порог/очередь/стиль/прерывание).

## Не входит в объём (следующие циклы)

- Режим последних кругов/атак (ляжет как модификатор важности + пресет стиля).
- «Гоночная память» кто-кого-атаковал (ляжет как источник `must_mention`).
- Расширение phrase bank (`commentator/templates.py`).
- Семантический анти-повтор (осознанно отклонён: CONTEXT.md запрещает новые слои
  дедупа поверх `SituationDedup`; корень чинится самим планировщиком).

## Архитектура

### Новый модуль `commentator/planner.py`

Чистые функции, без I/O и без сети — полностью юнит-тестируемы.

```python
@dataclass(frozen=True)
class CommentPlan:
    focus: str            # ЧТО именно комментировать, с резолвнутыми именами:
                          # "обгон: Норрис прошёл Пиастри"
    reaction: str         # тип реакции: "атака" | "авария" | "штраф" | "рекорд"
                          #   | "ремарка" | "разбор" | "финиш" | ...
    length: str           # "короткая ударная" | "обычная" | "развёрнутая"
    emotion: str          # "спокойно" | "оживлённо" | "на пределе"
    importance: int       # 0–100
    must_mention: tuple[str, ...]   # имена/факты, обязанные прозвучать

def score_importance(event: dict, ctx: PlanContext) -> int: ...
def build_plan(event: dict, importance: int, persona: str) -> CommentPlan: ...
```

`PlanContext` — маленький frozen-dataclass со срезом состояния гонки, который engine
собирает под своими локами и передаёт по значению (планировщик НЕ лезет в engine):
`player_involved: bool`, `battle: bool`, `laps_remaining: int | None`,
`session_type: str`, `gap_relevant_ms: int | None`.

### `score_importance` — базовая таблица + модификаторы

Базовый балл по `event_code` (все коды — из `core/packets.py::EVENT_DESCRIPTIONS` +
деривативные события engine):

| Код | База | Комментарий |
|---|---|---|
| COLL, RTMT | 90 | сегодняшние critical |
| PENA, RCWN, CHQF | 88 | сегодняшние critical |
| OVTK | 60 | +модификаторы ниже добирают до ~80 для игрока |
| FTLP | 55 | |
| DAMAGE_* | 65 | своя фраза уже готова (`phrase` preset) |
| F1_BENCH, CAREER_PB | 55 | |
| F1_SECTOR_BENCH, CAREER_SECTOR_PB | 45 | |
| SSTA, STLG | 70 | старт — всегда событие |
| SEND | 40 | |
| TMPT, SPTP, DRSE, DRSD | 30 | |
| FLBK | 25 | и так глушится flashback-тишиной |
| AMBIENT | 20 | фиксированно низкая — вытесняется всем реальным |
| STORY, USER_Q | вне планировщика | свои пути, см. «Не трогаем» |
| неизвестный код | 50 | нейтральный дефолт |

Модификаторы (суммируются, результат зажимается в [0, 100]):
`player_involved` +20; `battle` +15; `laps_remaining <= 3` +10 (задел под режим
финала); `session_type != "race"` −10 для OVTK/FTLP; событие с
`priority == "critical"` — пол 90 (`max(score, 90)`), чтобы ни один сегодняшний
critical не потерял своих гарантий.

### `build_plan` — маппинг важности в стиль

- `focus`: шаблон по `event_code` с уже резолвнутыми `driver`/`target` (entity
  resolution в `_commentary_loop` происходит ДО планирования — порядок сохранён).
- `reaction`: таблица код→тип (OVTK→"атака", COLL→"авария", PENA→"штраф", …).
- `length`/`emotion` от важности: ≥80 → «короткая ударная»/«на пределе»;
  50–79 → «обычная»/«оживлённо»; <50 → «обычная»/«спокойно». Персона сдвигает на
  ступень: `calm` понижает эмоцию, `hype`/`toxic` повышают.
- `must_mention`: непустые `driver`/`target` события.

### Промпт-директива в `commentator/brain.py`

`create()` получает новый опциональный параметр `plan: CommentPlan | None`.
При наличии плана `_compose()` ставит ПЕРВЫМ блоком директиву:

```
ЗАДАЧА: прокомментируй ИМЕННО это: {focus}.
Тип реакции: {reaction}. Стиль: {length}, {emotion}.
Обязательно упомяни: {", ".join(must_mention)}.
Остальной контекст ниже — только фон, НЕ пересказывай его.
```

Таймлайн, analytics_context, RAG и «НЕДАВНО СКАЗАНО» остаются как есть, ниже
директивы. При `plan=None` (fallback, ambient без плана) — поведение байт-в-байт
сегодняшнее.

### Четыре механизма в `core/engine.py`

**1. Порог «говорить/молчать».** Динамический порог `_speak_threshold(now)`:
базовый уровень ~35; сразу после озвученной фразы подскакивает до ~65 и линейно
спадает к базе за ~45 секунд. Событие с `importance < threshold` — пропуск в
feed с `muted=True` (как сегодняшний `_should_commentate`-отказ), **без вызова
LLM** — прямая экономия Yandex API. **Исключение — AMBIENT (importance 20 < базы
35):** порог к нему НЕ применяется — каданс амбиента уже полностью управляется
собственным адаптивным механизмом `_ambient_loop` (интервал/cooldown/throttle,
Task #14), второй фильтр поверх задушил бы его насмерть. Порог — только для
реальных событий; амбиент участвует лишь в очереди (вытесняется всем реальным). Взаимодействие с `MIN_COMMENT_GAP`:
importance ≥ 90 — гэп игнорируется (сегодняшнее critical-поведение);
80–89 — гэп режется вдвое; иначе — полный гэп. Константы — в `config.py`
(`PLAN_BASE_THRESHOLD`, `PLAN_SPIKE_THRESHOLD`, `PLAN_DECAY_S`), настройка без
переписывания логики (та же конвенция, что `AMBIENT_*`/`LLM_MIN_INTERVAL`).

**2. Приоритетная очередь.** `self.event_queue: queue.Queue` →
`queue.PriorityQueue` с элементами `(-importance, seq, event)` (`seq` —
монотонный счётчик: стабильный FIFO-порядок при равной важности и защита от
сравнения dict). Вытеснение бэклога: `_is_stale_backlog_event` заменяется
правилом «событие старше `PLAN_STALE_S` (~20с) И `importance < 70` — молча
пропустить» (штамп `enqueued_at` кладётся при put). Importance ≥ 90 не
вытесняется никогда. Все существующие точки `event_queue.put({...})` проходят
через новый хелпер `_enqueue_event(event)`, который считает важность один раз и
кладёт её в `event["importance"]` — скоринг НЕ размазывается по вызывающим местам.

**3. Стиль.** См. `build_plan` выше — важность уже внутри плана, engine ничего
дополнительно не делает.

**4. Прерывание озвучки.** Сегодня: `voice.say(phrase, priority="critical")`
прерывает текущую фразу. Новое правило: `priority="critical"` передаётся при
`importance >= config.PLAN_INTERRUPT_THRESHOLD` (=90). Так как все сегодняшние
critical получают пол 90, их поведение сохраняется 1:1; порог настраиваем.

### Поток данных (итоговый)

```
telemetry → parse_event → enrich → _should_commentate (как сегодня)
  → _enqueue_event: score_importance(event, ctx) → event["importance"]
  → PriorityQueue
_commentary_loop:
  get → порог говорить/молчать → staleness → entity resolution → session guard
  → flashback → SituationDedup → channel routing (всё как сегодня)
  → build_plan(event, importance, persona)
  → commentator.create(event, context, plan=plan)   # LLM формулирует по директиве
  → gap по важности → voice.say(priority по важности)
```

## Что сознательно НЕ трогаем

- `SituationDedup`, session guard, flashback silence, channel routing — без изменений.
- Шаблонный fallback `templates.render` (LLM недоступен) — без изменений; план
  влияет только на LLM-путь.
- Broadcast Director (`race_ai`), strategist (`strategy_ai`), radio-канал,
  `STORY`/`USER_Q` — свои пути генерации, планом не покрываются (у них
  `importance` считается только для очереди/порога, не для стиля).
- `_should_commentate` (позиция комментатора) — остаётся первым фильтром до очереди.
- Ambient-цикл — кладёт события через `_enqueue_event` c кодом AMBIENT (база 20),
  отдельной логики не получает.

## Отказоустойчивость

`score_importance`/`build_plan` — чистый Python. Обе точки вызова обёрнуты:
исключение → лог WARNING + `importance=50`, `plan=None` → событие идёт по
сегодняшнему пути. Поведение не может стать хуже текущего.
