# Гэп-дайджест инженера — дизайн (Фаза 2 из 4, «замена внутриигрового инженера»)

Дата: 2026-07-10
Статус: **черновик, реализован автономно** — пользователь отсутствовал 2 часа
(«отработай сам по комментатору, посмотри что осталось»), решения ниже приняты
агентом без интерактивного брейнсторминга. Требуют review пользователя
постфактум — отмечено явно в тексте, где решение неочевидно/на усмотрение.

## Контекст

Фаза 1 (точный box-вызов) и «голос инженера отдельно от комментатора»
закрыты (см. `2026-07-09-precise-box-call-design.md`,
`2026-07-09-engineer-voice-split-design.md`). Из утверждённого ранее списка
Фаз 2-4 пользователь выбрал порядок: box-вызов → **сводки по гэпу/секторам**
→ топливо/ERS → погода/трек-лимиты. Это — Фаза 2.

## Проблема

Настоящий инженер по радио даёт РЕГУЛЯРНЫЕ сводки по гэпам («отрыв полторы
секунды и растёт») независимо от того, происходит ли что-то «интересное» —
это ситуативная осведомлённость, не реакция на событие. Сегодня в Spotter App
это частично покрывает `_ambient_loop`, но: (а) он адаптивный по драме гонки
(в затишье реже, в буре чаще) — противоположная логика тому, что нужно для
рутинной сводки по гэпам; (б) он идёт через LLM — непредсказуемая по времени
и небесплатная (Yandex API); (в) он НЕ привязан к голосу инженера (до Фазы
«голос инженера» это было даже архитектурно невозможно).

## Решение (одним абзацем)

Новый независимый периодический поток `_engineer_digest_loop` (по образцу
`_ambient_loop`, но с ФИКСИРОВАННЫМ интервалом — гэп-сводка не должна
подстраиваться под драму, это рутинная осведомлённость) строит
ДЕТЕРМИНИРОВАННУЮ (без LLM) фразу из уже существующих `self._player_gap_front`/
`self._player_gap_behind` через новый чистый модуль
`core/strategy_ai/gap_digest.py::GapDigestTracker`, с трендом (растёт/
сокращается/стабильно) относительно ПРЕДЫДУЩЕЙ сводки. Событие
`ENGINEER_GAP_DIGEST` идёт с ГОТОВОЙ фразой (`event["phrase"]`) — это уже
существующий короткий путь в `_commentary_loop` (тот же, что использует
`F1_BENCH`/`PIT_EXIT`), полностью в обход LLM и `commentator/templates.py`.
`speaker: SPEAKER_ENGINEER` — голос `calm`, тот же механизм, что уже
переиспользуется с прошлой фазы.

## Автономные решения (нужен review пользователя)

Помечаю прямо то, что решил сам, без обсуждения — не факт, что угадал:

1. **Интервал: фиксированные 40 секунд**, не адаптивный. Обоснование:
   рутинная осведомлённость у настоящего инженера не зависит от того,
   идёт ли сейчас борьба за позицию — наоборот, именно ФОНОВЫЙ, предсказуемый
   каданс отличает эту сводку от адаптивного ambient. Если после проверки
   вживую покажется, что 40с — слишком часто/редко, это один константа
   (`config.ENGINEER_DIGEST_INTERVAL_S`), не архитектурное решение.
2. **Только `session_type == "race"`.** В отличие от box-вызова (Фаза 1,
   сознательно НЕ гейтован по типу сессии), гэп-сводка гейтуется — гэп к
   сопернику в квалификации/практике не несёт того же смысла (нет борьбы за
   позицию, только сольные круги). Асимметрия с Фазой 1 осознанная, не
   недосмотр — см. «Не входит в объём» ниже.
3. **Порог тренда: 300мс** между текущим и прошлым замером гэпа считается
   «заметным изменением» (растёт/сокращается), меньше — «стабильно».
   Взято по аналогии с другими 300-500мс порогами в `core/strategy_ai/`
   (`UNDERCUT_GAP_MAX_MS` и т.п.), не откалибровано на слух.
4. **Не комментируем сразу после значимого события** — переиспользую уже
   существующий `_in_event_cooldown()` (тот же, что душит ambient после
   аварии/обгона): не хочу, чтобы сухая цифра гэпа перебивала свежую драму.
5. **Формат фразы — только гэп, без секторов**, несмотря на название фазы
   в исходном списке («сводки по гэпу/секторам»). Секторное сравнение
   (кто быстрее в каком секторе) требует данных о секторах СОПЕРНИКА
   (`RivalTracker`/`opponents.py` — нужно проверить, что там реально
   доступно) — решил не блокировать гэп-часть (100% готовые данные) ожиданием
   секторной. Если пользователь хочет секторы — отдельное дополнение к этой
   же фазе, не блокер для того, что уже готово.

## Не входит в объём

- Секторное сравнение (см. п.5 выше) — возможное дополнение позже.
- Гэп до лидера (`gap_leader_ms`) — уже используется в других местах
  (F1-бенчмарк, career), не дублирую здесь; фокус на гэп ВПЕРЕДИ/СЗАДИ
  (тактически релевантно для «держать позицию»/«атаковать»).
- Адаптивность каданса — намеренно фиксированный интервал, см. п.1.
- Квалификация/практика — намеренно не гейтуется под них отдельным форматом
  (просто не идёт вообще, см. п.2).

## Архитектура

### Новый модуль `core/strategy_ai/gap_digest.py`

Чистый класс, без I/O — полностью юнит-тестируем, по образцу
`core/strategy_ai/box_call.py`.

```python
TREND_THRESHOLD_MS = 300

class GapDigestTracker:
    def __init__(self) -> None:
        self._prev_front_ms: int | None = None
        self._prev_behind_ms: int | None = None

    def build(self, gap_front_ms: int | None, gap_behind_ms: int | None) -> str | None:
        """Строит радио-фразу по гэпам. None — нечего сказать (нет данных)."""
        parts = []
        if gap_front_ms is not None and gap_front_ms > 0:
            parts.append(_gap_phrase("впереди", gap_front_ms, self._prev_front_ms))
        if gap_behind_ms is not None and gap_behind_ms > 0:
            parts.append(_gap_phrase("сзади", gap_behind_ms, self._prev_behind_ms))
        self._prev_front_ms = gap_front_ms
        self._prev_behind_ms = gap_behind_ms
        return " ".join(parts) if parts else None

    def reset(self) -> None:
        self._prev_front_ms = None
        self._prev_behind_ms = None


def _gap_phrase(label: str, gap_ms: int, prev_ms: int | None) -> str:
    gap_s = gap_ms / 1000.0
    if prev_ms is None:
        return f"Отрыв {label}: {gap_s:.1f}."
    delta = gap_ms - prev_ms
    if delta <= -TREND_THRESHOLD_MS:
        return f"Отрыв {label} сокращается, {gap_s:.1f}."
    if delta >= TREND_THRESHOLD_MS:
        return f"Отрыв {label} растёт, {gap_s:.1f}."
    return f"Отрыв {label} стабилен, {gap_s:.1f}."
```

Числа (`1.8` и т.п.) озвучиваются автоматически через уже существующий
`core/num_to_words.py::normalize()`, который вызывается в
`voice/tts.py::_play_blocking` для ЛЮБОГО текста, идущего в TTS — новый код
ничего специально для этого делать не должен (проверено: `_DECIMAL_RE`
матчит `1.8` внутри произвольного текста, включая перед точкой конца
предложения — `(?!\d)` требует не-цифру следом, точка подходит).

`gap_ms > 0` — фильтр (не `is not None`): 0 означает «сам лидер» или «машины
нет» в существующей конвенции (`commentator/timeline.py::_fmt_gap`
докстринг: «0 = нет машины / сам лидер»), не «нулевой отрыв».

**Найдено и исправлено ревью Task 1 (Important):** `build()` сохранял в
`_prev_front_ms`/`_prev_behind_ms` СЫРОЕ значение гэпа, включая `0`/`None`,
не нормализуя его так же, как для текущей фразы. Из-за этого переход «был
лидером (0, отфильтровано)» → «снова появилась машина впереди» считал
`delta` от нуля и почти всегда ложно объявлял «растёт» для совершенно нового
замера без реального тренда — ровно тот класс ошибки, который дизайн
изначально пытался исключить для ТЕКУЩЕГО тика, только на шаг в сторону (для
того, что запоминается как `prev`). **Фикс:** на хранение та же нормализация
(`gap_ms if gap_ms else None`), что и на фильтр текущего тика. Новый тест
`test_leader_to_real_gap_transition_has_no_false_trend`.

### `core/engine.py`

Инициализация рядом с `self.strategy_analyzer`:
```python
self._gap_digest = GapDigestTracker()
```

Новый поток в `start()`, рядом с `_ambient_loop`:
```python
threading.Thread(target=self._engineer_digest_loop, daemon=True,
                 name="engineer-digest").start()
```

Новый метод (по образцу `_ambient_loop`):
```python
def _engineer_digest_loop(self):
    while True:
        time.sleep(config.ENGINEER_DIGEST_INTERVAL_S)
        if (self._is_paused() or self._session_type != "race"
                or self._in_event_cooldown(time.time())):
            continue
        with self.state_lock:
            connected = self.state.get("connected")
        if not connected:
            continue
        phrase = self._gap_digest.build(self._player_gap_front, self._player_gap_behind)
        if phrase is None:
            continue
        self._enqueue_event({
            "event_code": "ENGINEER_GAP_DIGEST", "priority": "normal",
            "phrase": phrase, "speaker": SPEAKER_ENGINEER,
            "driver": "", "color": "#38BDF8",
        })
```

`event["phrase"]` преднабрана → `_commentary_loop` берёт её напрямую
(`phrase = event.get("phrase") or ""`), минуя LLM/`templates.render()` —
тот же короткий путь, что уже используют `F1_BENCH`/`PIT_EXIT`-подобные
события. `_REACTION_BY_CODE`/`_BASE_IMPORTANCE` НЕ нужны (используются только
внутри `build_plan()`, который вызывается лишь когда фраза НЕ преднабрана).

**Найдено и исправлено ревью Task 2 (Critical):** преднабранная фраза не
спасает от ДРУГОГО гейта — `_muted_by_threshold` (порог «говорить/молчать»,
`_commentary_loop`) срабатывает ДО короткого пути преднабранной фразы, а
`ENGINEER_GAP_DIGEST` без явной важности получает дефолт 50, который
систематически не перекрывал бы свежий спайк порога (65, до 85 в calm/story)
именно в загруженной гонке — там, где голосовая болтовня чаще, спайк почти
всегда свежий. Ровно обратное задуманному «не подстраиваться под драму
гонки». Фиксированная запись в `_BASE_IMPORTANCE` не решает для всех
режимов сразу (ниже 90 может не перекрыть calm/story-спайк 85, а ≥90
переключило бы приоритет на critical). **Фикс:** `"bypass_speak_threshold":
True` на событии — тот же приём, что уже применён к `PIT_CALL_NOTICE`
(«голос инженера отдельно от комментатора»). Новый regression-тест
`test_engineer_digest_survives_fresh_speak_threshold_spike`.

**Сброс `GapDigestTracker` на новой сессии** — рядом с уже существующим
сбросом `self._box_call_tracker.reset()` в блоке `if code == "SSTA":`
(иначе первая сводка новой гонки может ошибочно посчитать тренд от гэпа
из прошлой сессии):
```python
self._gap_digest.reset()
```


## Граничные случаи

- **Нет данных о гэпах** (игрок один на трассе / первый круг) —
  `build()` возвращает `None`, тик молча пропускается.
- **Гэп = лидер (0)** — фильтруется (`> 0`), не даёт ложного «отрыв 0.0».
- **Практика/квалификация** — цикл не строит фразу вообще (гейт по
  `session_type`), трекер не сбрасывается лишний раз (сброс только на
  `SSTA`, не на каждый тик).
- **Свежая авария/обгон** — `_in_event_cooldown()` откладывает тик (не
  теряется — просто следующий интервал попробует снова с уже устаревшим
  «prev», трек тренда чуть смажется, не критично).
- **Флешбек** — намеренно НЕ добавляю сброс `GapDigestTracker` в
  `_handle_flashback()` (в отличие от `_box_call_tracker`): худший случай —
  один раз неверно посчитанный тренд («растёт» вместо «стабильно») сразу
  после перемотки, не критично для этой сводки (в отличие от box-вызова,
  где неверный сброс дал бы неуместную команду «боксы»).

## Тестирование

- `tests/test_gap_digest.py` (новый) — чистая логика `GapDigestTracker`:
  первый замер (нет prev → без тренда), рост/сокращение/стабильность,
  фильтр `gap_ms > 0`/`None`, `reset()`, оба гэпа сразу в одной фразе,
  только один доступен, ни одного не доступен → `None`.
- `tests/test_engine_planner.py` — `_engineer_digest_loop` не юнит-тестируется
  напрямую (бесконечный цикл, та же конвенция, что и `_ambient_loop`/
  `_commentary_loop`), но `GapDigestTracker`/`SSTA`-сброс покрываются.
- Живая проверка (звучит ли сводка раз в ~40с голосом инженера во время
  гонки, не мешает ли другой болтовне) — недоступна в среде разработки,
  нужна пользователю.

**Найдено и исправлено финальным сквозным ревью всей Фазы 2 (Critical,
третий баг в этой фиче — до этого ревью уже нашло и починило два, см. выше):**
`bypass_speak_threshold` спасает событие ТОЛЬКО от `_muted_by_threshold` —
но ДО этого гейта в `_commentary_loop` стоит `_is_stale_backlog_event`,
который молча роняет событие с важностью < `PLAN_STALE_IMPORTANCE` (70),
если оно провисело в очереди дольше `PLAN_STALE_S` (20с). `ENGINEER_GAP_DIGEST`
(важность по умолчанию 50) в загруженной гонке — ровно там, где ОЧЕРЕДЬ
чаще занята событиями важнее (`OVTK=60`, `DAMAGE_*=65`, борьба/атака с
бонусами до 75-100) — мог отстояться дольше 20с и молча утонуть здесь, так
и не дойдя до `_muted_by_threshold`, где `bypass_speak_threshold` уже вроде
бы должен был его спасти. Тот же провал цели («не подстраиваться под драму
гонки»), что чинили дважды раньше, но через другой, независимый механизм.
**Фикс:** `bypass_speak_threshold` теперь также освобождает от
`_is_stale_backlog_event` — трактуется шире («это событие не должно молча
тонуть в очереди из-за общих механизмов анти-спама»), не только от порога
важности. Компромисс: чуть устаревший (на десяток-другой секунд) гэп всё
ещё представительнее полного молчания именно тогда, когда в гонке жарко.
Новый тест `test_bypass_speak_threshold_event_never_goes_stale` в
`tests/test_commentary_backlog.py`.

**Открытая находка ревью (не блокер, не чинили):** у фичи нет отдельного
тумблера (`engineer_digest_enabled`) — приглушить можно только всей
`commentary_enabled` или волюмом персоны `calm` (что заодно приглушит и
box-вызов/advisory). Если после живой проверки интервал/формат покажутся
навязчивыми, а не просто "надо потише" — рассмотреть отдельный тумблер в
`core/settings.py::DEFAULTS`, отдельной сессией.
