1. Режим «План» — 80% времени (Plan Mode)
Инструкция для Claude: Прежде чем писать хоть одну строчку кода, перейди в режим планирования (Plan Mode). Нажми Shift + Tab дважды, чтобы активировать его.
Твоя задача — проанализировать задачу, задать уточняющие вопросы и предложить детальный план действий. Не изменяй файлы, пока я не утвержу этот план. Мы должны разработать пошаговую стратегию, и только после моего подтверждения (/auto-accept) ты приступишь к её выполнению.

2. Живая Память: CONTEXT.md
Инструкция для Claude: В корне проекта есть файл CONTEXT.md. Это наша общая память. Ты должен постоянно его обновлять.

Если ты совершил ошибку или я дал тебе важное указание, ты обязан предложить: "Обновить CONTEXT.md, чтобы не повторять эту ошибку".

Ты должен сам добавлять в этот файл правила, инструкции по сборке, стилю кода и любые другие важные договоренности.

Содержи CONTEXT.md в порядке и не давай ему разрастаться до более чем 100 пунктов, чтобы избежать "дрейфа" модели.

3. Параллельная работа (Parallel Sessions)
Инструкция для Claude (и для меня): Для выполнения больших задач мы работаем параллельно. Я буду запускать несколько твоих экземпляров в разных терминалах (или вкладках). Каждый экземпляр будет работать над своей подзадачей в своем изолированном пространстве (например, в отдельной папке git worktree), чтобы избежать конфликтов.
Твоя задача — четко выполнять свою часть работы и сообщать о завершении, чтобы я мог переключиться на следующий экземпляр.

4. Специализированные Агенты (Subagents & Skills)
Инструкция для Claude: Для рутинных или сложных задач используй мои персональные скиллы и сабагенты.

Skills: Это мои "макросы" для частых задач, например, /commit-push-pr для создания пулл-реквеста или /code-simplifier для рефакторинга.

Subagents: Это специализированные агенты для конкретных задач, например, code-reviewer для проверки кода или test-writer для написания тестов.
Если я вызываю скилл или сабагента, ты должен действовать строго по его инструкциям.

5. Петля верификации (Verification Loop)
Инструкция для Claude: Твоя работа не заканчивается написанием кода. Ты должен сам себя проверить.
После того как ты написал код, ты обязан запустить тесты, линтеры или другие инструменты проверки, чтобы убедиться, что твои изменения не сломали ничего и соответствуют стандартам. Только после успешной самопроверки ты можешь сказать, что задача выполнена.

6. Модель: Opus 4.5 with Thinking
Инструкция для Claude: Для всех сложных задач по программированию используй модель Opus 4.5 with Thinking. Она может быть медленнее, но требует меньше правок и лучше работает с инструментами, что в итоге экономит время.

7. Автоматизация в Code Review
Инструкция для Claude: В процессе ревью кода мы используем тег @.claude в комментариях к пулл-реквесту. Если я или коллега напишем @.claude добавь это в CLAUDE.md, ты должен проанализировать контекст и предложить обновление для файла CLAUDE.md, чтобы автоматизировать этот процесс обучения.


Всегда придерживайся этого протокола. Начинай с планирования, затем выполняй, проверяй и документируй.
